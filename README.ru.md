# epic-board

[English version](README.md)

Локальная доска для работы, которая идёт сразу в нескольких репозиториях и по нескольким задачам, то есть для *эпика*. Здесь собрано то, что обычно лежит в истории чата и в голове:

- на каком шаге каждая задача;
- какая ветка к чему относится;
- какой MR зелёный;
- что сливать первым;
- что ждёт решения человека.

Доска поставляется как плагин [Claude Code](https://code.claude.com). Агент пишет на неё по ходу работы и читает её после сжатия контекста, поэтому длинная мультирепозиторная задача переживает `/compact` и новые сессии. Доской и CLI можно пользоваться и без агента.

- **Любой трекер.** У задачи любой идентификатор (`PROJ-12`, `#42`, `web-login`) и ссылка туда, где она живёт. Сама доска в трекер не ходит, это хранилище, в которое ты пишешь.
- **Факты из git, а не из памяти.** `refresh` делает один `git fetch` на репозиторий и пересчитывает каждую ветку: голову, отставание от базы, незапушенные коммиты, грязный ворктри. С `glab` или `gh` подтягивает состояние MR/PR и пайплайн.
- **Ждёт решения.** Пункт, который упирается в человека, содержит:
  - что именно нужно решить или сделать;
  - ссылки на задачи, шаги, ветки и документы;
  - необязательный чеклист. «Выполнено» не примется, пока в нём не отмечены все пункты.
- **Карта эпика.** Задачи показаны карточками со связями между ними. Открытая задача разворачивается в ленту шагов, рядом порядок слияния и цель.
- **Документы этапов.** Спеки, планы, журналы и ревью лежат рядом со своим шагом. Их можно хранить на доске или привязать из репозитория, смотреть и править на странице, есть версии.
- **Планы сессий.** Каждая сессия агента пишет, что делает и что дальше. Сессии Claude, Codex, Grok и Gemini видны рядом.
- **Экспорт.** Один самодостаточный HTML-файл только для чтения: можно отдать человеку, у которого доски нет.
- **Интерфейс** на английском и русском.
- **Порядок блоков.** Шестерёнка в заголовке эпика → «Порядок блоков»: перетащи плашки и сохрани. Порядок общий для всех эпиков на доске и сохраняется в HTML-экспорте.
- **Локально и без зависимостей.** Node ≥ 22, без npm-пакетов, сервис слушает только `127.0.0.1`, данные остаются в домашнем каталоге.

## Установка

### Плагин Claude Code

```text
/plugin marketplace add k-semenko/epic-board
/plugin install epic-board@epic-board
```

Дальше попроси агента установить сервис epic-board или сделай это сам из свежей версии плагина:

```sh
node "$(ls -d ~/.claude/plugins/cache/epic-board/epic-board/*/ | sort -V | tail -1)cli/epic.mjs" service install
```

`service install` делает три вещи:

- копирует приложение в `~/.local/share/epic-board/app`;
- держит данные в `~/.local/share/epic-board/data`;
- регистрирует пользовательский сервис: launchd на macOS, `systemd --user` на Linux.

После обновления плагина хук старта сессии сам обновит копию и перезапустит сервис. Доска открывается на <http://localhost:4747>.

Чтобы остаться на релизе, а не следовать основной ветке: `/plugin marketplace add k-semenko/epic-board#v0.5.0`.

### Из исходников

```sh
git clone https://github.com/k-semenko/epic-board.git
cd epic-board
npm test
node cli/epic.mjs service install      # или npm start — запуск в текущем терминале
```

Плагин из клона подключается так: `/plugin marketplace add /путь/к/epic-board`.

### Посмотреть без установки

```sh
npm run demo        # пример эпика во временном каталоге: http://localhost:4799/e/SHOP-1
```

## Как пользоваться

```sh
alias epic='node cli/epic.mjs'   # или путь внутри кэша плагина
epic new SHOP-1 --title "Оплата на одной странице" --goal "Покупатель платит на одной странице"
epic repo SHOP-1 web --path ~/src/web --base main --provider github --project github.com/acme/web
epic task SHOP-1 WEB-31 --title "Форма оплаты" --url https://tracker.example.com/WEB-31 --status "В работе"
epic step SHOP-1 WEB-31/card --title "Ввод карты" --state active
epic branch SHOP-1 WEB-31 web feat/payment-form --mr 412
epic wait SHOP-1 add psp --title "Выбрать платёжного провайдера" --details "Сравнить комиссии и возвраты" \
  --ref step:WEB-31/card --check "Комиссии сравнены" --check "API возвратов проверено"
epic refresh SHOP-1
epic url SHOP-1
```

Все команды выводит `node cli/epic.mjs help`. Примеры лежат в [`skills/epic-board/reference/cli.md`](skills/epic-board/reference/cli.md), модель данных — в [`reference/schema.md`](skills/epic-board/reference/schema.md).

## Настройка

Файл `~/.config/epic-board/config.json`, все ключи необязательны:

| Ключ | По умолчанию | Что значит |
|---|---|---|
| `dataDir` | `~/.local/share/epic-board/data` | где лежат эпики, история и документы |
| `port` | `4747` | порт сервиса |
| `host` | `localhost` | имя хоста в ссылках; заодно разрешённый `Host`. Например, имя, которое ты направил на `127.0.0.1` в `/etc/hosts` |
| `publicUrl` | — | адрес за обратным прокси, например `http://board.example` без порта; ссылки строятся по нему, его хост разрешён |
| `stripProxy` | `false` | убирать `HTTP(S)_PROXY` для git, glab и gh, если прокси не пропускает к внутренней площадке |

Ключи можно переопределить переменными окружения: `EPIC_BOARD_HOME` (каталог данных), `EPIC_BOARD_PORT`, `EPIC_BOARD_STRIP_PROXY=1`.

`node cli/epic.mjs doctor` показывает, что видит сервис:

- инструменты;
- авторизацию на каждом хосте площадки;
- `git ls-remote` зарегистрированного репозитория.

## Безопасность

- Сервис слушает только `127.0.0.1`.
- Заголовки `Host` и `Origin` проверяются, это защита от DNS rebinding.
- Документы отдаются только из каталога данных и из репозиториев, описанных в эпике.
- Имена веток проверяются до того, как попадут в git.
- Наружу сервис ходит только через настроенные тобой `git`, `glab` и `gh`.

Как сообщить об уязвимости, написано в [SECURITY.md](SECURITY.md).
